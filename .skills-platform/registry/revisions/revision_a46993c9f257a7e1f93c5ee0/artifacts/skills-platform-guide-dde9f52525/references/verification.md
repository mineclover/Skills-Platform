# 사용 확인과 복구

## 완료 근거

| 단계 | 확인할 증거 |
| --- | --- |
| 선택/등록 | 직접 설치할 source/name 또는 Catalog의 revision/preset/project ID |
| 파일 전달 | CLI 설치 출력, 대상의 `SKILL.md`, 실제 링크 대상 또는 adapter report |
| 호스트 발견 | 대상 프로젝트의 새로고침된 스킬 목록과 정확한 이름/경로 |
| 작업에서 사용 | 작은 요청에 해당 스킬이 선택되고 기대한 결과가 나온 기록 |

Codex에서는 `$skills-platform-guide`처럼 명시적으로 호출할 수 있다. 다른 호스트는
해당 호스트의 호출 방법을 따른다. 이름이 같으면 경로까지 비교한다. 호스트 목록이나
실제 호출에 접근할 수 없으면 파일 전달까지만 검증했다고 보고한다.

## 증상에 따른 조치

| 증상 | 확인과 다음 조치 |
| --- | --- |
| 목록에 없음 | 프로젝트 CWD와 설치 범위, CLI 대상 경로, 호스트 검색 경로, `SKILL.md` 이름과 frontmatter를 확인 |
| 링크가 끊김 | 실제 링크 대상의 존재와 체크아웃 이동 여부 확인. 해당 관리 도구로 재구성 |
| 같은 이름이 여러 개 | 프로젝트/전역/내장/플러그인 출처를 구분하고 사용할 경로를 특정. 삭제·비활성화는 요청된 정리 범위에서만 수행 |
| CLI에는 있는데 호스트에 없음 | 호스트 enablement와 검색 경로 차이 점검. 호스트가 권장하는 새로고침 또는 재시작 후 재확인 |
| 업데이트해도 내용이 같음 | 직접 설치는 source/lock/복사 여부, Catalog는 선택한 revision/digest와 적용 report를 비교 |
| recipe digest 불일치 | 원본 변경을 검토하고 새 digest/revision으로 갱신. 불변 snapshot 수정이나 일치 검사 우회 금지 |
| ownership 충돌 | 현재 소유자와 사용자 수정 확인 후 관리 경로 전환. 강제 삭제나 sidecar 조작으로 우회하지 않음 |

`project status`의 `managed`는 sidecar가 읽혔다는 관찰값이다. 외부 CLI가 그 sidecar를
존중한다거나 대상 내용이 검증되었다는 보장은 없다. 실패 시 동일 명령을 반복하기보다
오류가 가리키는 단계에서 원인을 좁힌다.

간단한 검증 요청 예: “이 프로젝트의 스킬 설치 방식과 다음 업데이트 경로를 알려줘.”
단순 안내에서는 설치나 설정 변경 없이 답해야 한다.
