# 구축 맥락 기록 — WorkflowContext

> 기존 문서·이슈의 절로 사용해도 된다. 새 데이터 구조나 별도 파일은 필수가 아니다.
> `<...>`는 작성할 자리다. 모르는 값을 임의로 채우지 않는다. 확인된 값·제안·미확정을 구분한다.

## 1. 참조와 호출

| 항목 | 값·정본 참조 |
|---|---|
| 맥락 식별 | <식별값> |
| 인식 방식 | <전체 인식 / 변경분 인식 / 최신성 확인 후 재사용> |
| 출처 상태 | <established / proposed, 유효한 정본·지정 근거> |
| 구축 절차 정본 | <경로·앵커 + revision> |
| 작업 상태 정본 | <경로 + revision 또는 확인 시점> |
| 대상 실행 파이프라인 | <경로 + revision, 아직 없으면 생성 대상> |
| 목표·필수 제약 | <정본 참조> |
| 이번 호출의 기준 단계 | <프로젝트의 실제 구축 단계 ID> |
| 다른 활성 단계 | <병렬·하위 단계, 없으면 없음> |
| 이번 요청 | <해야 할 작업과 기대 산출물> |

## 2. 관련 구축 단계

| 단계 ID·목적 | 진입 입력·조건 | 수행 활동·담당 | 산출물·정본 | 완료 기준·판정 주체 | 실패·후속 경로 | 현재 상태 |
|---|---|---|---|---|---|---|
| <ID·목적> | <선행 산출물·조건> | <작성·결정·검사 등> | <참조> | <검사·증거·주체> | <분기·재작업·합류> | <프로젝트 상태> |

현재 단계와 그 선행 조건·영향받는 후속 단계는 상세하게 작성한다. 나머지 단계는 절차 정본을 참조한다. 하나의 선형 목록으로 병렬·재작업 경로를 없애지 않는다.
