# 🛑 Post-Planning Review Gate Protocol
## (계획 수립 후 중간 검토 관문 상세 프로토콜)

---

## 1. 목적 (Purpose)

계획 수립(P01~P04)과 아키텍처/사양 문서 작성이 완료된 시점에서 파이프라인의 **불필요한 코드 변경 착수를 방지**하고, 사용자가 설계와 검증 기준을 사전에 확정하도록 보장하는 결정론적 검토 관문입니다.

---

## 2. 검토 체크리스트 (Review Checklist)

검토 관문 진입 시 에이전트와 사용자는 다음 항목을 확인합니다:

1. **비목표(Non-goals)가 명확한가?**
   * 작업 범위가 불필요하게 커지는 스코프 팽창(Scope Creep)을 방지하도록 비목표가 작성되었는지 확인.
2. **수용 검사(Acceptance Checks)가 기계적으로 측정 가능한가?**
   * 주관적인 평가가 아닌 구체적인 테스트 스크립트 또는 evaluator URI(`evaluator://...`)가 바인딩되었는지 확인.
3. **의무(Obligations)의 순서와 의존성 DAG가 올바른가?**
   * 선행 작업(`depends_on`)이 올바르게 지정되어 차단 없이 순차 해결될 수 있는지 확인.
4. **수정 허용 파일 화이트리스트(`allowed_change_scope`)가 좁게 한정되었는가?**
   * 의도하지 않은 레거시 파일 수정을 차단하도록 스코프가 격리되었는지 확인.

---

## 3. 실행 모드 선택 가이드 (Execution Mode Selection)

```text
┌───────────────────────────┬────────────────────────────────────────────────────────┐
│ 실행 모드                 │ 선택 기준                                              │
├───────────────────────────┼────────────────────────────────────────────────────────┤
│ Direct In-Tree Mode       │ • 변경 파일 수가 1~3개 이내의 단일 버그/기능 패치       │
│                           │ • 워크트리 생성 및 병합 큐 대기 시간 없이 빠른 적용 원함 │
│                           │ • 단일 에이전트 순차 작업                              │
├───────────────────────────┼────────────────────────────────────────────────────────┤
│ Worktree Isolation Mode   │ • 다중 모듈 수정 또는 복잡한 대규모 아키텍처 변경     │
│                           │ • 미검증 코드가 작업 디렉터리를 오염시키는 것을 방지  │
│                           │ • 검증 통과 후 자동 Fast-Forward 병합 큐 활용          │
└───────────────────────────┴────────────────────────────────────────────────────────┘
```
